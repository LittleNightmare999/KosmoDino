# КосмоДино

**Интерактивная энциклопедия космоса и динозавров**

> Академический проект. Курсовая работа по дисциплине «Программная инженерия».
> Автор: Гуляева Анастасия Павловна, группа 25-КБ-ПИ1, 2026.
> Проект создан в учебных целях, не является коммерческим продуктом и не содержит монетизации.

КосмоДино — веб-приложение для чтения и редактирования энциклопедических статей по двум разделам: «Космос» и «Динозавры». Статьи связаны между собой в граф знаний, расположены на хронологической шкале и сопровождаются викторинами. Публикация проходит через редакционный процесс: черновик, рецензирование, публикация или отклонение с замечанием.

## Возможности

Права пользователей задаются ролями. Каждая следующая роль включает возможности предыдущей.

| Роль | Возможности |
| --- | --- |
| Гость | Чтение опубликованных статей, полнотекстовый поиск, фильтрация по категориям и тегам, хронологическая шкала, граф связей, регистрация |
| Читатель | Комментарии, закладки, прохождение викторин, личная статистика, редактирование профиля и смена пароля |
| Редактор | Создание и правка статей, карточка фактов, связи между статьями, вопросы викторин, история ревизий, отправка на рецензию |
| Администратор | Рецензирование (публикация и отклонение), архивирование и удаление статей, управление пользователями и ролями, модерация комментариев, справочник категорий, журнал действий, сводная статистика |

### Жизненный цикл статьи

```
черновик ──► на рецензии ──► опубликована ──► в архиве
    ▲             │                ▲               │
    └── отклонена ◄┘                └───────────────┘
```

Допустимые переходы и роли, которым они разрешены, заданы одной таблицей правил в сервисном слое. Каждая правка создаёт ревизию, каждое действие редакции записывается в журнал.

### Решения для работы под нагрузкой

- **Полнотекстовый поиск PostgreSQL** с русской морфологией и GIN-индексом по заголовку, описанию и тексту; результаты ранжируются по релевантности.
- **Буферизованный счётчик просмотров**: просмотры копятся в памяти процесса и раз в три секунды записываются в базу одним относительным `UPDATE` на статью. Читатели популярной статьи не ждут блокировку строки, несколько рабочих процессов сервера не конфликтуют.
- **Кэш с ограниченным временем жизни** (15–30 секунд) для справочников и каталога; сбрасывается при изменении статей.
- **Пул соединений** SQLAlchemy и сжатие ответов GZip.
- **Составные индексы** по состоянию и разделу статьи, индексы всех внешних ключей.

### Безопасность

- Пароли хранятся только в виде хеша PBKDF2-SHA256 с солью.
- Аутентификация по токену JWT в заголовке `Authorization`.
- Ролевая модель доступа проверяется на сервере для каждого запроса; интерфейс лишь скрывает недоступные действия.
- Редактор может изменять только собственные статьи; заблокированный пользователь не может войти.

## Архитектура

Приложение построено по трёхуровневой схеме.

```
┌──────────────────────┐    HTTP / JSON + JWT    ┌──────────────────────────┐    SQL    ┌──────────────┐
│   Браузер            │ ──────────────────────► │   FastAPI (Uvicorn)      │ ────────► │ PostgreSQL 16│
│   React-клиент (SPA) │ ◄────────────────────── │   маршрутизаторы         │ ◄──────── │   (Docker)   │
└──────────────────────┘                         │   сервисный слой         │           └──────────────┘
                                                 │   модели и схемы данных  │
                                                 └──────────────────────────┘
```

- **Маршрутизаторы** (`backend/app/routers`) принимают запросы и проверяют права доступа.
- **Сервисный слой** (`backend/app/services`) содержит бизнес-правила: жизненный цикл статьи, журнал действий, кэш, счётчик просмотров.
- **Модели** (`models.py`) описывают таблицы базы данных, **схемы** (`schemas.py`) — формат данных программного интерфейса.
- Собранный клиент раздаётся тем же сервером, поэтому в рабочем режиме приложение доступно по одному адресу.

## Быстрый запуск

### Требования

- Windows 10 или 11
- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- [Python 3.12+](https://www.python.org/downloads/)
- [Node.js 20+](https://nodejs.org/)

### Запуск

```
start.exe
```

Программа проверяет инструменты, запускает Docker Desktop при необходимости, поднимает контейнер с базой данных, создаёт виртуальное окружение Python, устанавливает зависимости, наполняет базу, собирает клиент и запускает сервер. После запуска приложение открывается по адресу <http://127.0.0.1:8000>.

| Команда | Действие |
| --- | --- |
| `start.exe` | Подготовить окружение и запустить приложение |
| `start.exe --reset` | Пересоздать базу данных и наполнить её заново |
| `start.exe --test` | Запустить автоматические тесты сервера и клиента |
| `start.exe --stop` | Остановить контейнер базы данных |

Сервер и контейнер останавливаются при закрытии окна консоли.

Пересобрать `start.exe` из исходников (нужен .NET 10 SDK):

```
dotnet publish launcher -c Release -o launcher/publish
```

## Ручной запуск

Порядок действий без `start.exe`, например для разработки.

**1. База данных**

```
docker compose up -d db
```

PostgreSQL доступна на порту `5433`.

**2. Сервер**

```
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app.seed.seed
uvicorn app.main:app --reload --port 8000
```

Документация программного интерфейса: <http://127.0.0.1:8000/docs>.

**3. Клиент в режиме разработки**

```
cd frontend
npm install
npm run dev
```

Клиент доступен по адресу <http://localhost:5173>, запросы к `/api` перенаправляются на сервер.

### Настройки

Параметры сервера читаются из переменных окружения с префиксом `ENC_` или из файла `backend/.env`.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `ENC_DATABASE_URL` | `postgresql+psycopg://encyclopedia:encyclopedia@localhost:5433/encyclopedia` | Подключение к базе данных |
| `ENC_JWT_SECRET` | учебное значение | Ключ подписи токенов; при развёртывании обязательно заменить |
| `ENC_ACCESS_TOKEN_MINUTES` | `720` | Срок действия токена |
| `ENC_DB_POOL_SIZE` | `10` | Размер пула соединений |
| `ENC_VIEWS_FLUSH_SECONDS` | `3.0` | Период записи просмотров в базу |

## Тестирование

```
start.exe --test
```

Или по отдельности:

```
cd backend
.venv\Scripts\python -m pytest
```

```
cd frontend
npm test
```

Серверные тесты работают с отдельной базой данных `encyclopedia_test` и не затрагивают основную.

| Набор | Что проверяется |
| --- | --- |
| `test_auth` | Регистрация, вход, профиль, смена пароля |
| `test_catalog` | Каталог, поиск, фильтры, хронология, граф |
| `test_reader` | Комментарии, закладки, викторины |
| `test_workflow` | Жизненный цикл статьи и ревизии |
| `test_admin` | Рецензирование, пользователи, модерация, журнал |
| `test_security` | Разграничение доступа по ролям, хранение паролей |
| `test_concurrency` | Одновременные запросы и счётчик просмотров |
| `units`, `screens` | Компоненты и экраны клиента |

### Нагрузочный тест

При запущенном приложении:

```
backend\.venv\Scripts\python backend\scripts\load_test.py --requests 3000 --concurrency 50
```

Скрипт отправляет смешанный поток запросов читателей и выводит пропускную способность, процентили задержки и долю ошибок.

## Программный интерфейс

Все адреса начинаются с `/api`. Полное описание со схемами доступно в Swagger по адресу `/docs`.

| Группа | Основные методы |
| --- | --- |
| Аутентификация `/api/auth` | `POST /register`, `POST /login`, `GET` и `PATCH /me`, `POST /me/password` |
| Каталог `/api` | `GET /topics`, `GET /tags`, `GET /articles`, `GET /articles/{slug}`, `GET /timeline/{topic}`, `GET /graph` |
| Читатель `/api` | комментарии, закладки `/me/bookmarks`, викторины `/quiz/{topic}`, `/quiz/submit`, статистика `/me/stats` |
| Редакция `/api/editor` | статьи, отправка на рецензию, ревизии, связи между статьями, вопросы викторин |
| Администрирование `/api/admin` | статистика, рецензирование, архив, пользователи, комментарии, категории, журнал |
| Система | `GET /api/health` |
